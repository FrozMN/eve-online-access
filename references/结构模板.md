# 结构模板

EVE 攻略材料可归为四类文体，各有固定骨架。**先定文体，再套骨架**——混用会导致读者找不到关键信息（该给数值的地方在讲故事，该讲风险的地方在做罗列）。

| 文体 | 读者的问题 | 结构重心 |
|------|-----------|----------|
| **机制手册** | "规则到底是怎么算的？" | 规则 → 公式 → 实例 → 数据附录 |
| **实操攻略** | "我该怎么做这一步？" | 准备 → 流程步骤 → 配置 → 风险 |
| **速查表** | "这个情况我该选哪个？" | 对照表 → 选择心法 |
| **新人入门** | "我现在该去做什么？" | 线性流程 → 检查清单 |

---

## 一、机制手册

**适用**：解释一套规则体系（势力战争、任务机制、工业链、声望系统）。
**特征**：长、含公式、含数据附录、随版本频繁修订。

````markdown
# <机制名>手册

<一句话定位读者：这篇文档帮你摆脱什么状态>

文档版本 v<X.Y> ｜ 最后更新：YYYY-MM-DD ｜ 数据时点：YYYY-MM

> **本次修订**：<改了什么、依据哪个版本/补丁>。与原文冲突处用 ⚑ 标注，旧结论以 ~~删除线~~ 保留。

## 目录

- [[#1. 核心规则]]
- [[#2. 计算方式]]
- [[#附录 1：数值表]]

## 1. 核心规则

<规则说明，分条列出>

- <情形 A>：<结果>
- <情形 B>：<结果>
- ⚑ <版本日期> 变更：<新规则>（原为 ~~<旧规则>~~）

## 2. 计算方式

$$
<公式> = <变量 A> \times (1 + <系数>)
$$

例：<把具体数值代进去，给出结果>

## 3. 变化轨迹

| 日期 | 版本/资料片 | 相关改动 |
|:---|:---|:---|
| YYYY-MM-DD | <补丁号> | <要点> |

## 附录 1：<数值表>

| 项目 | 基础值 | 条件 | 备注 |
|:---:|:---:|:---|:---|
| | | | |

> 数据时点 YYYY-MM；官方数值会随版本调整，以游戏内为准。

## 附录 2：<公式/点数表>

## 参考来源（YYYY-MM-DD）

- 官方补丁说明：<版本号>
- <联盟/社区 Wiki 页面>

> 本文与后续补充均以游戏内实际表现为准；官方数值会随版本再调整。
````

**检查点**：

- [ ] 有文档版本号与数据时点
- [ ] 每个公式配一个代入数值的实例
- [ ] 改版处用 ⚑ 或删除线标注，旧值未被删除
- [ ] 数值集中放附录，正文只讲逻辑
- [ ] 来源按补丁号/页面可追溯
- [ ] 结尾有"以游戏内为准"的免责

## 二、实操攻略

**适用**：教读者完成一件具体的事（挖坟、跑快递、刷某类任务、配置某类船）。
**特征**：步骤化、配截图、必须写风险。

## 三、速查表

**适用**：数值/选项的快速对照（弹药、无人机、装备、舰船、税率、距离表）。
**特征**：以表格为主体，配"选择心法"把表串起来。

````markdown
# <主题>速查表

> 整理自 <来源 1>、<来源 2>、<来源 3> 等公开资料。**数据时点：YYYY-MM**。
> <哪些会变、哪些长期有效>——例如："伤害/射程等绝对数值会随版本调整，请以游戏内为准；本文的档位关系、伤害类型与选品逻辑一般长期有效。"
> 相关入口：[[<中心页>]]

## 目录

- [[#<体系 A>速查]]
  - [[#<子表 1>]]
  - [[#选择心法]]
- [[#<体系 B>速查]]

## <体系 A>速查

### <子表 1>

| 项目 | 数值 | 单位 | 备注 |
|:---:|:---:|:---:|:---|
| | | | |

### <子表 2>

### 选择心法

<把表格串成可执行的判断规则：什么情况选哪个，什么情况避免哪个>

## <体系 B>速查

## 参考来源与整理说明

| 来源 | 用途 |
|:---|:---|
| <官方 / Wiki / 数据库> | <核对什么> |
````

**检查点**：

- [ ] 开头即声明数据时点与来源
- [ ] 明确划出"长期有效"的内容范围
- [ ] 表格含单位与条件列（不能只有数字）
- [ ] 每个体系有"选择心法"，不让读者自己推
- [ ] 存在多来源的，用 `source_refs` 或表格列出
- [ ] 数值与来源可逐项对应（便于后续核对）

## 四、新人入门

**适用**：帮新玩家从零到"能用"（装客户端、注册、绑定平台、加入语音、认识基础概念）。
**特征**：线性流程、每页一件事、以官方来源为主、少用黑话。

````markdown
# <本页要解决的一件事>

## <步骤标题：一件事>

<正文：说清"做什么 + 为什么"，避免行话>

建议通过 [<官方入口>](<链接>) <操作>。 <补充关键动作与判断标准。>

> <次要信息放引用块：后果说明或小提示>

## <下一个步骤>

<同上；每一步对应一个二级标题，标题即动作>

:::tip <可选：常见疑问>
<回答一个新人最可能问的问题>
:::

## <场景>前的检查清单

- **<红线项：做错会直接损失资产的>**
- <逐项检查：环境、资源、设置>

## 推荐阅读（可选）

- [<官方或社区教程>](<链接>)
````

**检查点**：

- [ ] 每页只解决一件事，标题即动作
- [ ] 步骤顺序符合新人的真实经历，不跳步
- [ ] 以**官方**来源为主（官方新手指引、帮助中心）
- [ ] 提供当前有效的组织入口（如适用），不放已失效链接
- [ ] 术语首次出现即有解释，**不使用未解释的黑话**
- [ ] 结尾有检查清单，含至少一条"红线项"
- [ ] 页间有编号与互链，构成阅读路径

---

## 通用：任何文体都要有的三块

无论用哪套骨架，以下三块不可缺：

1. **时点声明**——数据时点 + "以游戏内为准"。可在开头一句、或数值表下方
2. **来源列表**——文末列出，可追溯（补丁号、Wiki 页面、原作者）
3. **风险提示**——涉及资产的，至少一处明确警告（容器块或加粗红线句）

## 通用：写作顺序建议

```
① 先写数值与结论（表格先行）   ← 数据是骨架
② 再写操作/规则步骤             ← 把骨架串起来
③ 最后写前言、心法、风险提示    ← 读者视角的导航
④ 复查时点、来源、红线项        ← 交付前必做
```

> 先写正文再补数值，容易写成"看起来完整但没法照着做"的文章。
