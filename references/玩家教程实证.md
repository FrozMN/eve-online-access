# 玩家教程的实证写法

从 **58 篇玩家实战教程（约 68 万字）** 中统计出来的写法规律。不是"应该怎么写"的理想，而是"玩家实际怎么写、且读者愿意读"的模式。

写作时对照本文，产出会更像圈子里的教程，而不是产品说明书。

---

## 一、开篇：三行内让人决定读不读

### 1.1 实测的高频开场元素

| 元素 | 出现比例 | 说明 |
|---|---:|---|
| 署名行（作者/创作者 + 昵称）| 常见 | `作者：XXX（昵称）`、`创作者：联盟 · 公司 · 昵称` |
| 指明读者对象（萌新/新人）| **59%** | 直接说"给萌新"、"献给欧服新人" |
| 写明读完能得到什么 | **43%** | 「看完了本篇你会…」「你将…」|
| 点明收益或代价 | **45%** | 每小时收益、启动资金、技能时间 |

### 1.2 四种真实开场类型

| 类型 | 特征 | 实战样本（节选）|
|---|---|---|
| **故事/设问** | 用一段叙事或连续反问把人带进情境 | 「EVE，一个远离地球的未知世界……这一切，还得从 21 世纪的地球说起。」|
| **直给干活** | 明说不写客套，直接上结论 | 「没有前言直接干货」|
| **吐槽自嘲** | 用玩梗表达痛点，建立同类感 | 「"今天刷了多少？"——团里的催工梗」|
| **目的-产出清单** | 并列「为什么写」与「你会得到什么」 | 「写本篇的目的有：扫盲 / …；看完了本篇你会：…」|

### 1.3 硬要求

> **开篇 100 字内必须出现三件事之一**：这篇解决什么问题、读完能做什么、代价与收益是多少。

只写"本文将介绍 XX"的开头，玩家会直接关掉。

## 二、结构：名词分节，按时序推进

### 2.1 分节命名

- 用**名词短语**：`声望`、`宣战`、`击杀权`、`进洞准备`、`压洞`
- **不要**用"第一章 / 第一节 / Part 1"——玩家教程里几乎不出现
- 同一页内层级不超过 3 级

### 2.2 章节顺序 = 操作时序

实测主流骨架（按出现频率归纳）：

```text
署名 → 为什么写 / 你会得到什么 → 前提（技能、资金、船型）→ 准备（装备、地点、消耗品）
→ 步骤（编号，配图）→ 收益与成本 → 风险与规避 → 常见问题 / 踩坑合集 → 更新记录
```

### 2.3 收尾三选一

| 收尾方式 | 适用 |
|---|---|
| 踩坑合集 / 常见死法 | 新人向、风险高的题材（样本：《EVE 隐藏傻逼死法集锦》）|
| 收益总结表 | 生产、刷怪、任务类 |
| 更新记录与致谢 | 长期维护的机制手册 |

## 三、语气：第二人称 + 条件句 + 明确建议

### 3.1 实测数据

| 特征 | 数据 |
|---|---|
| 第二人称「你」 | 全样本 **1,780 次**（平均每篇 30 次）|
| 条件句「如果……就……」 | **86%** 的教程使用 |
| 风险提示词（注意/小心/切记/务必） | **74%** 的教程出现 |
| 建议词（建议/推荐/别/不要） | **47%** |
| 风险/损失描述（损船、被抓、炸船） | **55%** |

### 3.2 直接下判断，不说"可能可以试试"

```diff
- 玩家可以考虑根据自身情况选择是否使用巡洋舰进行作业。
+ 新人就用狂怒者级，别上巡洋舰以上的船，一条船 3 亿你赔不起。
```

### 3.3 条件句承载决策

```text
如果你的技能还没到 T2 炮，就先在 00 刷集会点，别碰圣坛。
如果你是多开，把打捞号单独挂一个星系，别跟主号同星系。
```

### 3.4 梗与吐槽放在括号/删除线里

- 允许：「摆烂狂怒（真的能摆，但收益会掉一半）」
- 禁止：把玩笑写进数值表或标题
- 自嘲式表述能拉近距离，但**任何一处玩笑都不能让人误解数值**

### 3.5 面向组织时给具体动作

```diff
- 打捞的垃圾可以卖给军团回收。
+ 垃圾交给军团回收，按每立方 10m ISK 结算，频道见群公告（公开版写"按军团当期价格"）。
```

## 四、格式偏好（实测）

| 项 | 实测 | 建议 |
|---|---|---|
| 编号 | 中文「1、」7/58 篇；Markdown 列表 29/58 篇 | 两种都可读，**发布到站点统一用 Markdown 列表/有序列表** |
| 配图 | **35/58 篇带图**（共 638 张）| 图必须跟一句说明：「点开 Industry 之后，出现工业页面，分为蓝图、设置、任务三个分支」|
| 表格 | 广泛用于对照（配置、收益、抗性）| 数值表必须带**单位**与**前提列** |
| 粗体 | 集中在关键数值与结论 | 一段里不要超过 2 处 |
| 花哨排版 | 极少 | 不用引用块堆砌、不用多层嵌套列表 |

## 五、数值怎么写才好用

### 5.1 收益三件套

```text
前提：技能 X / 船型 Y / 星系 Z / 是否多开 / 单次时长
产出：每小时 A ISK（或每个异常 B ISK）
成本：弹药 + 损耗 + 时间（含往返跳数）
```

缺任意一项，收益数字就不可复现。

### 5.2 风险写到"能规避"

| 差 | 好 |
|---|---|
| 「注意安全」 | 「进 00 前先看本地人数与朝向，过门后立刻朝向下一个门；被泡泡拦下时不要回头，跳安全点」|

### 5.3 成本分三段

`启动资金`（船+装备+弹药）→ `每周期支出`（消耗品/燃料）→ `回本周期`（按当前收益估算，标时点）

## 六、常见反面写法

| 反模式 | 为什么劝退 | 改法 |
|---|---|---|
| 只写步骤不写前提 | 读者条件不同，照做就亏 | 前置「前提」段落 |
| 大段机制理论不讲结论 | 读者要的是能不能做 | 结论前置，机制放附录 |
| 数值不标时点 | 版本一动全错 | 表格标「数据时点：YYYY-MM」|
| 通篇"可以/也许/视情况" | 等于没给建议 | 给默认方案 + 例外条件 |
| 标题只用黑话 | 搜不到、新人看不懂 | 标题用可检索说法，黑话放正文并首次给官方名 |

## 七、改写示例

### 例 1：新人刷怪开篇

```diff
- 本文介绍在零安地区进行异常空间刷怪的相关内容。
+ 想靠刷怪赚第一桶金，看这篇就够了。
+ 前提：能开战列舰、有 T2 抗性装备、所在星系是蓝加主权；单号每小时约 1.2 亿 ISK（数据时点 2026-10）。
+ 看完你会：知道刷哪种点、怎么配船、被堵门时怎么跑。
```

### 例 2：风险段

```diff
- 零安地区存在一定风险，请注意防范。
+ 零安最大的死法不是被打死，是过门被泡泡拦住还回头。
+ 过门后先朝下一个门，看到泡泡直接跳安全点，别想着反打——你一条战列的 DPS 打不穿拦截舰的逃跑速度。
```
