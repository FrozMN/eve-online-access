# 写作规范：共同特点

本文汇总自一批长期维护的 EVE 中文攻略材料（机制手册、实操攻略、速查表、新人问答），提炼出可复用的共同特点。

> 脱敏说明：本文所有具体人名、组织名、内部频道与价格均已替换为占位符或示例标注。示例中的数值仅用于说明写法，不代表任何组织当前的政策。

---

## 一、结构特点

### 1. 前言先交代"值不值得"

不铺垫背景，直接回答读者最关心的问题：**这件事收益如何、代价是什么、适合谁**。

> 实例（实操攻略）：
> 「就收益而言，<这种做法> 的效率是基本不如 <另一种做法>。但 <它的独有价值> 与之高度绑定……如果你厌倦了 <主流玩法>，想尝试新的生产方式，那么本篇教程可能对你有所帮助。」

> 实例（机制手册）：开头一句「点开文档，迈出脱离 <某机制> 云玩家的一大步！」——一句话定位读者画像。

### 2. 长文配目录，短章用清单

- 长文（>100 行）设「目录」，按小节分级列出（Markdown 知识库中用锚点链接）
- 中等篇幅用小节标题 + 要点清单，不写大段散文

### 3. 数值进附录/表格，正文讲逻辑

机制手册把收益表、点数表、NPC 数据表全部放**附录**，正文只讲"怎么算、怎么选"：

```
正文：解释计算公式与影响因素
附录 1：基础收益表（含 dps 要求、承伤要求、预估时间）
附录 2：点数表
附录 3：PVE 过程 NPC 数据表（dph / dps / 有效生命值）
附录 4：示意图
```

### 4. 分层递进的准备清单

明确区分**必备**与**推荐**：

> 实例：
> `*必须*准备：` 一条能完成该任务核心动作的船、在界面中确认目标位置、确认环境风险等级
> `推荐准备：` 更耐打的船体、提升效率的植入体、提前向频道确认路况、预做安全点

> 实例（新人页面）：开游前检查清单——身体状态、资源完整性、语音、加速器

### 5. 章节顺序遵循操作时序

```
准备 → 流程 → 配置 → 注意事项 → 附录/参考来源
```

## 二、内容取向

### 1. 风险提示贯穿全文（而非单设"风险"章节）

每一个可能损船的环节都就地提示，而非集中放在末尾：

| 材料类型 | 就地风险提示实例 |
|------|--------------|
| 实操攻略 | 「<风险环境> 可能过门被泡泡逮住」、「本地不定期刷新 <敌对玩家>，建议立刻停止并跃迁到安全点」、「怪没有反跳，挖完直接走人」 |
| 市场类 | 独立 `:::warning` 块讲**宣战与强暴**两种合法击毁情形 |
| 任务类 | 「别跳 0，避免卡建筑损」、「**永远不要让代理人声望小于 <阈值>**」、「使用假隐跳技巧来土路」 |
| 新人入门 | 「不使用加速器……极有可能导致舰船损失」 |
| 服务类 | 快递「必须填写保证金，未填写的合同会被拒接」、「合同内不能包含箱子」 |

### 2. 数据精确到可直接决策

不写"收益不错"，写**具体数字 + 单位 + 条件**：

```
10000 × (1 + 50%) = 15000 点
基础设施血量：7.5m 盾 + 7.5m 甲，合计 15m 有效
护卫 NPC 速度 2500 → 4000 m/s、信号半径 40 → 80m
<产出物>：每个货柜有概率出 3–5 个，按每个 <单价> 回收
```

### 3. 版本敏感性显式管理

四种手段并用：

| 手段 | 用途 | 实例 |
|------|------|------|
| **数据时点声明** | 标明数据对应的时间 | 「数据时点：YYYY-MM（当前版本）」 |
| **版本号 + 更新日期** | 文档自身版本化 | 「<手册名> v1.4」、「<改版方>改一次，我就改一次（YY/MM/DD）」 |
| **删除线保留旧值** | 展示变化轨迹 | `~~旧规则：额外乘以 75%~~ 现与另一种收益相同（YYYY-MM-DD 改版）` |
| **`⚑` 标记差异** | 标注与原文/其他来源不一致 | 「⚑ YYYY-MM-DD 补充：该结论**仅在 <特定状态> 成立**」 |

> 并且明确划出"长期有效"边界：
> 「伤害/射程等绝对数值会随版本调整，请以游戏内为准；本文的档位关系、伤害类型与选择逻辑一般长期有效。」

### 4. 跨来源冲突显式列出

机制手册专设「**待确认差异**」小节：

> - <某项收益>：原文记 10,000 且"1 小时内由攻击者均分"；EVE University Wiki（YYYY-MM）记 **15,000 / 每名造成过伤害的玩家（无时限）**——两者出入较大，待游戏内确认。
> - <某项加成>：原文记 2%，EVE Uni 记 ~1%——以游戏内实测为准。

速查表则在开头或结尾列出全部来源，正文注明整理自哪几处。

### 5. 面向组织语境的落地路径

不止讲机制，还给**读者所在组织内的具体做法入口**——但**公开版本必须泛化**：

| 内部版本 | 公开版本（改为占位符或角色描述） |
|---|---|
| 「加入 <某频道>（感谢 <某成员> 开源）」 | 「加入组织内的 <某用途> 频道」 |
| 「在 <某频道> 找到 <某任务> 频道」 | 「在组织内部频道中完成配置」 |
| 「直接找 <某成员>」 | 「联系组织的 <角色：回收对接人 / 招新官>」 |
| 「产物运到 <某集结点>，也可挂给 <某成员> 回收」 | 「产物运往组织集结点，或按内部回收渠道处理」 |
| 「按每个 <具体价格> 回收」 | 「按当期内部回收价（示例：<数量级>）」 |

### 6. 翻译/转载要标清来源与完成度

> 实例：
> 「原教程链接：<原始地址>
> 本文为对 <原作者> *未完成教程* 的简单翻译并手工校对版本，**可能存在错误，仅供参考**。」

即：原文链接 + 原作者 + 完成度 + 免责。

## 三、格式规范

### 1. 标点与空格

| 规则 | 示例 |
|------|------|
| 中英文之间加空格 | `EVE Online 客户端`、`100w 自由技能点`、`检查 Mumble 语音设置` |
| 全角中文标点 | `，。；：、（）`——不用半角 `,.;:` |
| 枚举用顿号 | `跳跃星门、锁定、激活装备、频道发言` |
| 链接两侧加空格 | `建议通过 [官网安装](url)。` |
| 产品名按官方写法 | `ISK`（非 isk）、`Omega`（非 OMEGA）、`PLEX`、`Mumble` |

> 新写内容统一用 `ISK`；早期材料中 `isk` 混用属遗留，不必照抄。

### 2. 术语处理

- 机制名首次出现给英文全称：`出勤 PAP（Participation Points）`、`LP（loyalty points，忠诚点）`
- 舰船：社区昵称 + 首次标注可检索的正式名
- 保留圈内黑话但保证可理解：挖坟、绕杆子、土路、白嫖、损、跳 0、种菜

### 3. 公式用 LaTeX

```markdown
$$税前收益 = 基础收益 \times (1 + 状态系数)$$
```

### 4. 数值表格带单位与条件列

收益表类内容的推荐列结构：

| 项目 | 基础数值 | 门槛要求 | 承伤要求 | 预估时间 |
|:---:|:---:|:---:|:---:|:---:|
| <项目 A> | 100,000 | 见制式要求 | 见制式要求 | 约 30–40min |

### 5. 危险信息用容器块

Markdown 知识库：`> [!warning] <后果描述>！`
静态站点：`:::warning <标题>`

容器内内容**顶格写**（缩进 4 空格会被渲染成代码块，链接会失效）。

### 6. 图片作为流程图示

操作类教程大量使用截图，且**按步骤编号**：

```
1. <第一步说明>![[<截图>.png]]
2. <第二步说明>![[<截图>.png]]
3. <第三步说明>![[<截图>.png]]
```

截图需能让读者对照自己的界面判断"这一步做对了没有"。

## 四、语气范式

| 手法 | 实例 | 作用 |
|------|------|------|
| **开门见山的判断** | 「效率是基本不如……但……那么本篇教程可能对你有所帮助」 | 先给结论，节省读者时间 |
| **自嘲/牢骚用删除线** | `~~显然他自己教程都没写完我们咋拒绝~~` | 保留个人风格，不干扰正文 |
| **括号内交代出处与不确定性** | `（感谢 <某成员> 开源）`、`（价格或有调整）` | 标清来源与时效 |
| **点名的具体路径** | 「找 <角色>」「<用途>频道」「<集结点>」 | 让读者知道下一步去哪 |
| **文末趣事** | 「文末趣事：有效没 4000 还敢抓标隐？」 | 收尾放松，兼作经验分享 |
| **警句式加粗** | 「**永远不要让代理人声望小于 <阈值>**」 | 标记不可违反的红线 |

## 五、新人材料的额外要求

入门类内容与机制攻略不同，遵循**线性流程 + 官方来源**：

1. 按新人实际经历排序：认识游戏 → 客户端账号 → 势力与组织 → 首次登录 → 内部平台与语音
2. 引用**官方**来源为主（官方新手指引、帮助中心、官方站数据）
3. 提供**当下有效**的组织入口链接（注册链接、内部平台、服务官网），并标注"以最新公告为准"
4. 少用黑话，首次出现的术语必须解释
5. 每个页面在板块 index 中有序号，形成阅读路径
