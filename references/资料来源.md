## 二级：组织内部来源（占位符，按自己的组织替换）

写组织内部文档时，这类来源是**唯一权威**（政策、价格、对接人会变，公开 Wiki 不覆盖）。

| 类型 | 占位符 | 提供什么 | 注意事项 |
|------|--------|----------|----------|
| 组织 Wiki / 文档站 | `<联盟/军团 Wiki 地址>` | 服务总览、规则、教程 | 公开与内部内容可能混排，引用前确认是否对外可见 |
| 内部认证平台 | `<SeAT 地址>` | 角色绑定、出勤、补损 | 需登录；引用时不要贴带 token 的链接 |
| 注册/招募链接 | `<注册链接>` | 新人注册入口（常带返利） | **含返利参数，不可公开发布** |
| 快递服务 | `<快递官网>` | 运费、保证金规则 | 价格随时调整，须标"以最新公告为准" |
| 回收 / 回购服务 | `<回购服务地址>` | 报价流程、回收范围 | 同上 |
| 内部论坛 | `<论坛地址>` | 公告、教程帖、招新 | |
| 内部语音/消息平台 | `<平台与频道说明>` | 集结通知、日常沟通 | 服务器地址与频道名属内部信息 |
| 战绩统计 | https://zkillboard.com/ | 组织与成员击杀记录（公开可查） | 用组织 ID 查询；**公开版本不要写具体组织 ID** |

> ⚠️ **常见失效问题**：组织 Wiki 的旧页面常有死链（如指向已删除的频道页）。引用前逐个验证，必要时改用同类可访问页面替代，并在文中说明替换原因。

## 内容落点与自检

写作前先确认**已有的内容落在哪里**，避免重复与冲突：

| 落点 | 路径特征 | 检查项 |
|------|----------|--------|
| 公开文档站 | 仓库内 `docs/<lang>/` | 是否已有同主题页面；`_meta.json`/侧边栏是否需要新增条目 |
| 组织内部文档 | 组织 Wiki / 频道置顶 | 是否与最新政策一致；是否需要走内部审阅 |
| 个人知识库 | 本地 Markdown 库 | 是否已存在草稿；是否需与正式版合并 |

## 核对策略

```
① 机制类内容   → 官方帮助中心 + 英文社区 Wiki 双向核对
② 数值类内容   → EVE Ref（官方译名与属性）+ 游戏内实测；标数据时点
③ 版本改动     → 官方补丁说明（按版本号逐个查）
④ 组织内部流程 → 内部 Wiki + 最新公告（以最新通知为准）
⑤ 价格/收益    → 游戏内市场或组织服务页；注明"价格或有调整"
```

**冲突处理**：不默默采信。列出双方数值 + 各自出处 + 标注"待游戏内确认"，写在专门的「待确认差异」小节中。

**时点原则**：任何引用来的数值，进入文档时都要带上"数据时点：YYYY-MM"，否则读者无法判断是否过期。
